## Backend gate: the fixture defect the no-row state exposed, fixed

The first no-row run failed 20 methods, all on one teardown assertion ("the platform's own
provider row is put back"): the test classes stored the captured row in a
`Property SavedProvider As %DynamicObject`, and assigning "" — the "there was no row" sentinel —
to an object-typed property coerces it into an oref-shaped value, so the restore guard
`If saved = ""` never fired and the teardown tried to write a garbage row. The dev machine always
carried a row, so the CI state had never been exercised until this gate. Fixed by declaring the
property `%RawString` in StepSearchServiceTest / StepCorpusTest / StepTypeSearchTest; the suite
then passed 302/302 with count = 0, as recorded above.
